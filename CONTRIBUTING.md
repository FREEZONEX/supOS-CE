# Contributing to Tier0 Edge

Thank you for helping improve Tier0 Edge.

## Before opening a pull request

- Search existing issues and pull requests to avoid duplicate work.
- Keep each change focused and include documentation updates when installation or configuration behavior changes.
- Run the relevant checks for the code you changed and describe the result in the pull request.
- Do not commit generated runtime files, credentials, private keys, database data, or local `.env` files.

## Reporting bugs

Include the Tier0 Edge version, host operating system, Docker and Docker Compose versions, steps to reproduce, expected behavior, actual behavior, and relevant sanitized logs or screenshots.

## Pull request review

Use a clear title and explain the problem, solution, validation, and any deployment or compatibility considerations. Maintainers may request changes to keep the public edition secure, installable, and compatible with its documented deployment boundary.
